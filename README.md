# AntAF · 蚂蚁阿福体重秤大屏

把蚂蚁阿福体重秤（AFU-WL-TZ-A1）接入本地电脑，实时称重、自动估算 18 项身体成分，并在 iPad / 平板上以四宫格大屏仪表盘展示。支持多成员档案：**先测量、再把记录归属到人**，体成分按每位成员的身高、年龄与性别独立计算。

> 秤本身只回传重量与阻抗，且只有一个用户槽位；历史记录与「这次是谁称的」全部由本项目在本地维护。

## 功能

- **实时称重**：BLE 直连私有服务，重量随踩秤即时刷新，稳定后自动建档（单位 kg，精确到 0.01 kg）；
- **阻抗测量**：连接后自动下发时间 + 用户资料包，使能阻抗测量，收到阻抗后按 BIA 公式本地估算体成分；
- **多成员档案**：姓名、身高、年龄、性别、标识色；新增 / 修改 / 删除，资料变更后自动重算该成员名下全部记录；
- **先测量后归属**：每次稳定读数先生成一条「待分配」记录，再在页面上选择成员完成归属，归属关系可随时修改；
- **18 项身体成分**：BMI、体脂率、脂肪量、内脏脂肪等级、皮下脂肪率 / 量、体水分率 / 量、蛋白质含量 / 占比、骨量 / 占比、肌肉量 / 率、骨骼肌量 / 率、基础代谢、去脂体重，带等级的指标附分级标签；
- **iPad 大屏布局**：横屏四宫格（实时测量 / 成员档案 / 身体成分 / 测量记录），竖屏与手机自动堆叠，支持全屏与深 / 浅主题；
- **本地持久化**：成员与记录保存在 JSON 文件中，服务重启不丢失；同一称重的重复稳定帧自动合并，阻抗帧补全到同一条记录。

## 环境要求

- Windows 10 / 11，电脑具备可用蓝牙；
- Python 3.10+；
- Chrome / Edge 等现代浏览器（局域网内的平板 / 手机也可访问）。

## 快速开始

```powershell
# 首次运行
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 启动服务
.\.venv\Scripts\python.exe server.py
```

启动后终端会打印访问地址：

```
访问地址：
  http://127.0.0.1:8765
  http://192.168.x.x:8765
```

本机打开 `http://127.0.0.1:8765`；iPad / 平板在同一 Wi-Fi 下打开 `192.168.x.x` 地址（Windows 防火墙弹窗请勾选「专用网络」）。

### 启动参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--host` | `0.0.0.0` | 监听地址，局域网访问保持默认 |
| `--port` | `8765` | 监听端口 |
| `--token` | 空 | 访问令牌。设置后需用 `http://IP:端口/?token=令牌` 打开 |
| `--no-scale` | 关闭 | 禁用体重秤读取（仅调试页面时使用） |

| `--scale-height` | `173` | 首个成员的身高（厘米），用于触发阻抗测量与体成分估算 |
| `--scale-age` | `25` | 首个成员的年龄（岁） |
| `--scale-sex` | `male` | 首个成员的性别，`male` / `female` |
| `--weight-store` | `weight/weight_store.json` | 成员档案与测量记录的持久化文件路径 |

## 协议（实测）

秤使用私有服务 `0xFFB0`：写入特征 `FFB1`、通知特征 `FFB2`，**无需配对、无需认证**。服务启动后会自动连接扫描到的 `AFU*` 设备。

通知帧共 20 字节，包头 `0xAC`，`data[1]` 为设备型号（本机 `0x29`），包类型在 `data[18]`，序号在 `data[19]`：

```
体重包 0xD5    ac 29 | <32 位体重编码> | … | 29 d5 | 序号
阻抗包 0xD6    ac 29 02 | <通道数> | <2 字节×通道数> | <mode> | <32 位体重编码> | … | 29 d6 | 序号
资料应答 0xD8  ac 29 01 | … | … | 29 d8 | 序号
```

体重编码是 32 位大端数：低 18 位为克数，`bit18-20` 为刻度精度（division），**`bit31` 为稳定标志**。换算（1 个计数 = 1 克）：

```
kg = (编码 >> 0) & 0x3FFFF  →  克数，再按 division 档位取整为显示值
```

该关系用三个实测点验证过，误差为 0：`6889994 → 74.250 kg`、`6890044 → 74.300 kg`、`6829744 → 14.000 kg`。称重过程中帧间隔约 120 ms，可做实时滚动；稳定后连续推送结果帧。

阻抗包的 `data[2]` 是通道数，真正的阻抗值在 `data[4:4+2*count]`（每通道 2 字节大端），本机 `count=2`，实测光脚 `583/536 Ω`、`637/580 Ω`，穿袜子时 `699/642 Ω`（接触电阻更大）。

### 体成分资料包（0xD0）

秤默认只称体重，**不会**主动测阻抗。要拿到体成分，必须在连接后向 `FFB1` 下发「时间 + 用户资料」包（包类型 `0xD0`），使能功能位 `0x03`：

```
AC | 型号 | 时间4B(大端) | 时区(15min单位) | 单位0 | 用户号1 | 身高
   | 档案体重00 | 年龄 | 性别(1男/2女) | 目标体重00 | 功能位03 | 00 | D0 | 校验和(2..18求和)
```

服务连上秤后立即下发资料包，并每 15 秒重发一次；秤收到后回 `0xD8` 应答，随后称重结束才会发出 `0xD6` 阻抗包。收到阻抗后由 [body_composition.py](weight/body_composition.py) 按体重、阻抗、身高、年龄、性别本地计算。

默认资料为 **身高 173 cm、年龄 25 岁、男性**（可用 `--scale-height/--scale-age/--scale-sex` 修改；服务启动后也可在页面「成员档案」中维护）。

## 多成员档案与记录归属

秤只有 1 个用户槽位，也不会告诉服务「这次是谁称的」，因此「记录归谁」完全由本地管理：

1. **先测量**：任意成员光脚上秤，服务在稳定读数出现时立即建档（同一次称重的重复稳定帧自动合并为一条记录，后续到达的阻抗帧会补全到同一条）；
2. **再归属**：记录初始为「待分配」，「测量记录」里每行右侧都有归属按钮，也可在「实时测量」卡片右侧的成员列表里一键归属最新一条记录；
3. **按人重算**：归属后服务端用**该成员**的身高 / 年龄 / 性别与本次阻抗重新执行 BIA，体成分因此与「谁称的」一致；修改成员资料后，其名下所有记录的体成分会自动重算；
4. **同步秤资料**：最近一次被归属的成员资料会作为下发给秤的用户资料包（只用于使能阻抗测量，体成分以本地重算为准）。

成员支持姓名、身高、年龄、性别与自动分配的标识色；名下有记录时禁止删除（避免历史记录失去归属），记录可单独删除。数据保存在 `weight/weight_store.json`，服务重启后不丢失，也可用 `--weight-store` 指定其他路径。

对应的 WebSocket 指令：`add_user` / `update_user` / `delete_user` / `assign_record`（`user_id` 传 `null` 取消归属）/ `delete_record`；变更后会向所有页面推送 `weight_state`。

## 指标与分级

页面共展示 18 项指标（BMI + 17 项身体成分），带等级的指标会在数值下方显示等级标签（绿 = 标准 / 优秀，黄 = 偏低 / 不足，红 = 偏高 / 高 / 过高）：

| 指标 | 单位 | 等级 | 计算 / 分级依据 |
| --- | --- | --- | --- |
| BMI | — | 无 | 体重 / 身高² |
| 内脏脂肪等级 | 级 | 标准 / 高 | `BMI×0.3 − 年龄×0.05 + 0.4`（限 1–50）；1–9 标准，≥10 高 |
| 体脂率 | % | 偏低 / 标准 / 偏高 / 过高 | BIA 公式；按性别与年龄分段阈值 |
| 脂肪量 | kg | 同体脂率 | 体重 × 体脂率 |
| 皮下脂肪率 | % | 偏低 / 标准 / 偏高 | 体脂率 × 0.71，阈值按同比例缩放 |
| 皮下脂肪量 | kg | 无 | 体重 × 皮下脂肪率 |
| 体水分率 | % | 偏低 / 标准 / 偏高 | `(100−体脂率)×0.7` 修正；男 50–65%，女 45–60% 为标准 |
| 体水分量 | kg | 同体水分率 | 体重 × 体水分率 |
| 蛋白质含量 | kg | 不足 / 标准 / 优秀 | 去脂体重 × 0.238；占比 16–20% 标准，>20% 优秀 |
| 蛋白质占比 | % | 无 | 蛋白质含量 / 体重 |
| 骨量 | kg | 偏低 / 标准 / 偏高 | BIA 公式；按性别与体重分档标准区间 |
| 骨量占比 | % | 无 | 骨量 / 体重 |
| 肌肉量 | kg | 偏低 / 标准 / 优秀 | 体重 − 脂肪量 − 0.85×骨量；按性别与身高分档 |
| 肌肉率 | % | 同肌肉量 | 肌肉量 / 体重 |
| 骨骼肌量 | kg | 偏低 / 标准 / 偏高 | 肌肉量 × 0.558；参考 Janssen MRI 男 33 kg / 女 21 kg，±10% 为标准 |
| 骨骼肌率 | % | 同骨骼肌量 | 骨骼肌量 / 体重 |
| 基础代谢 | kcal | 无 | Mifflin-St Jeor（1990） |
| 去脂体重 | kg | 无 | 体重 − 脂肪量 |

> **标准说明**：真正有权威依据的只有 Mifflin-St Jeor 基础代谢公式、AWGS 2019 肌少症 ASM 口径与 WHO 的 BMI 分界；体脂率分龄阈值、内脏脂肪公式、骨量 / 肌肉量分档、水分 / 蛋白质 / 皮下脂肪区间均来自厂商 SDK 或社区实现（ha-miscale2、icomon_scale、ant-afu-welland-scale、Omron / Tanita 说明书），**属于经验参考值，不能作为医学诊断依据**，不同品牌之间不可直接比较。
>
> 体成分是**基于 BIA 公式的估算值**，不是医疗级测量；阻抗受脚底湿度、站姿、袜子影响较大，请固定条件、光脚测量。

## 使用

1. **踩一下秤**唤醒它（休眠时不会广播，服务就搜不到）；
2. **光脚**站上去保持不动约 2 秒，页面先显示「称重中」，稳定后变「测量完成」；
3. 稳定后稍等 1–3 秒，秤补发阻抗包，记录里会带上阻抗；
4. 在「实时测量」右侧或记录行里**选择成员完成归属**，左下「身体成分」随即按该成员资料展示 BMI 与 17 项指标；
5. 穿袜子只会得到更大的阻抗（甚至测不到），此时该记录仅有体重，归属后也不显示体成分。

页面为 iPad 大屏仪表盘布局：横屏（≥1081px）为四宫格 —— 左上实时测量、右上成员档案、左下身体成分、右下测量记录；竖屏与手机自动堆叠，顶栏「全屏」按钮可铺满屏幕。

## 故障排查

| 现象 | 可能原因与处理 |
| --- | --- |
| 页面一直显示 `--` | 秤处于休眠；踩一下唤醒。仍无反应时确认秤在附近、设备名以 `AFU` 开头（可用 `--scale-match` 指定其他前缀） |
| 启动提示「蓝牙扫描启动失败」 | 适配器被禁用、驱动异常，或系统隐私设置禁止应用访问蓝牙 |
| 局域网设备打不开 | Windows 防火墙未放行、平板与电脑不在同一网段、路由器开启了 AP 隔离 |
| 体重读数偏小 | 单脚压秤只读到部分重量，需双脚站稳静止约 2 秒；秤应放在硬质平整地面 |
| 阻抗一直为 `--` 或为 `0 Ω` | 未光脚 / 穿了袜子 / 脚底太干；擦干脚底光脚站稳，等秤补发阻抗包 |
| 有体重但没有体成分 | 阻抗未测到（同上），或记录尚未归属成员；先在页面选择归属，服务会按该成员资料重算 |
| 成员无法删除 | 该成员名下还有记录，先把记录归属到其他成员或删除记录 |

## 文件结构

```
server.py                  BLE 扫描、WebSocket / HTTP 服务、成员与记录指令
weight/
  scale_reader.py          体重秤连接、资料下发与重量 / 阻抗解析
  records.py               成员档案与测量记录的存储、归属与体成分重算
  body_composition.py      基于 BIA 公式的体成分估算
  web/
    index.html             仪表盘结构
    weight.css             仪表盘样式（深浅主题、大屏布局）
    weight.js              前端逻辑（WebSocket、实时测量、成员与归属、体成分）
requirements.txt           Python 依赖
```
